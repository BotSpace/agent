# Bot qurish qo'llanmasi (ixcham)

Bot flow'ini `flow.*` tool'lari bilan O'ZING quriladi. Node tiplarining QISQA
katalogi yuqorida (nom + bir qatorli tavsif). To'liq maydon/schema kerak bo'lsa —
**oldindan hamma narsa yuborilmaydi**, `flow.list_node_types(type=...)` bilan
kerakli node(lar)ning aniq schemasini SO'RAB OL, keyin qo'sh.

## Ish oqimi (lazy — token tejaydi)
1. Katalogdan kerakli node tiplarini tanla.
2. **`flow.list_node_types` — MAJBURIY, `flow.add_node`dan OLDIN.** Katalog faqat
   node NOMI + bir qatorli tavsifni beradi — MAYDONLARNI EMAS. Shuning uchun
   ISHLATADIGAN HAR node tipini (TRIGGER'lar ham!) birinchi marta qo'shishdan OLDIN
   uning aniq schemasini `flow.list_node_types(types=["A","B",...])` bilan OL —
   bitta ham node'ni "bilaman" deb tashlab ketma. **Maydon nomini HECH QACHON
   TAXMIN QILMA.** Eng ko'p uchraydigan XATO taxminlar va TO'G'RISI:
   - ReplyButtonTriggerNode: `buttonText` YO'Q → `selectedButtons`.
   - Klaviatura: `keyboard`/`replyMarkup` YO'Q → `keyboard_kind` ('inline'|'reply')
     + `rows` (tugma qatorlari ro'yxati).
   - CallbackQueryTriggerNode: `withArgs` YO'Q → callback'ni filtrlash uchun
     `filter` ('starts_with'|'equals'|…) + `context: {value: "prefix_"}`; qiymatni
     saqlash uchun `state_key` + `state_type` yetarli (alohida `save_state`
     switch yo'q). Keyingi node'da `{{state_key}}` EMAS, aynan `{{key}}`
     ishlat: masalan `state_key="phone"` → `{{phone}}`.
   - Dinamik ro'yxat/klaviatura (collection'dan): `rows`ga `{{#each}}` TEMPLATE
     ISHLAMAYDI — `rows` statik ro'yxat. Collection'dan dinamik tugmalar uchun
     `LoadCollectionListNode` → `CustomCodeNode` (JS'da `rows` yasab `send_message`).
   Butun toifa kerak bo'lsa `flow.list_node_types(category="payment"/"ai"/...)`.
3. `flow.add_node(id, type, data, after?)` bilan qo'sh — `data` faqat 2-qadamda
   OLINGAN schemadagi maydonlar bilan, OBYEKT sifatida (JSON string EMAS). Har node
   uchun alohida typed tool YO'Q; hammasi `flow.add_node` orqali. Noma'lum maydon =
   "Extra inputs not permitted" xatosi va behuda turn.
4. Ulash: `flow.connect` / `flow.connect_button` / `flow.connect_branch` /
   `flow.connect_accessory`.
5. `flow.validate`dagi `unknown_variable`/`legacy_state_reference`ni harmless deb
   o'tkazib yuborma — ular CMS'ga bo'sh qiymat yozadi. Tuzat → `flow.save`
   (approval so'ramaydi) → **`flow.simulate` bilan
   O'ZING sina** (6-band) → tugagach `release.debug`.

## Save'dan keyin SINA — MAJBURIY (o'tkazib yuborma)
Bot qurib/tahrirlab `flow.save` qilganingdan keyin foydalanuvchiga topshirishdan OLDIN
uni O'ZING tekshir — bu qadamni HECH QACHON tashlab ketma:
1. `flow.simulate` va `flow.test_save`/`flow.test_run` — bular **lazy** tool'lar, tool
   ro'yxatingda TO'LIQ berilmagan. AVVAL `tools.search(query="simulate")` (yoki
   `query=["simulate","test"]`) bilan schemasini YUKLA, keyin chaqir.
2. `flow.simulate(project_id=<joriy>, steps=[...])` — REAL bot/Telegram'siz asosiy
   stsenariyni yugurtir (masalan `/start` → tugma bosish → matn kiritish). Har qadamga
   `expect` (contains/keyboard_contains) qo'shib javobni AVTOMATIK tasdiqla. Ko'p
   stsenariyda `mode="assert"` — kompakt "✅ 9/10 o'tdi" (token tejaydi).
   ⚠️ **`expect`ni node'dagi AYNAN matndan yoz** — o'zingdan paraphrase QILMA. `contains`
   uchun xabar matnining bir bo'lagini xuddi yozilganidek (emoji/harf-registri bilan) ol;
   `keyboard_contains` uchun tugma matnini AYNAN nusxala. `click_text`da ham tugma matni
   1:1 mos bo'lsin. Collection'dan keladigan qiymat kutsang — seed'dagi HAQIQIY qiymatni
   ishlat (simulyator collection'ni real data bilan to'ldiradi). Mos kelmasa — expect'ni
   emas, matn/tugmani tekshir; qisqa `contains` + `no_errors` ko'pincha yetarli.
   ⚠️ `flow.simulate`/`flow.save`da `project_id`'ni HAR DOIM uzat.
3. Xato/bo'sh javob chiqsa → tuzat → qayta `flow.save` → qayta `flow.simulate`.
   Foydalanuvchidan so'rashdan OLDIN o'zing yechib qo'y.
   ⚠️ Qadam **"0 xabar [—]"** (hech qanday node ishlamadi) bo'lsa — trigger shu
   input'ga MOS KELMADI (buyruq/tugma matni), YOKI `use_saved=true` bilan ESKI
   saqlangan flow'ni sinayapsan. Bunday holda oxirgi qo'shgan node'ni AYBLAMA —
   avval trigger'ni tekshir va tahrirdan keyin `flow.save` qilganingga ishonch
   hosil qil (yoki `use_saved=false` bilan working flow'ni sina).
   Bir xil `0/N` natija ikki marta takrorlansa taxmin bilan node qo'shib-o'chirishni
   TO'XTAT: `mode="full"` + `use_saved=false` bilan bitta diagnostika qil; sabab
   chiqmasa `flow.history`/`flow.rollback` orqali oxirgi ishlagan versiyaga qayt.
4. Bot tayyor bo'lgach asosiy stsenariylarni `flow.test_save(name, steps)` bilan
   REGRESSION test sifatida saqla — keyingi tahrir eski oqimni jimgina buzmasin
   (`flow.test_run` bilan qayta tekshiriladi).
Simulyator vaqtincha ishlamasa ("Simulyator servisi ishga tushmagan") — `release.debug`
bilan debug botda sinashni taklif qil.

## INTENT → SPEC (qurishdan oldin)
Yangi qurishda (working_flow bo'sh) qurishdan OLDIN ichingда qisqa spec o'yla:
triggerlar, asosiy oqim, ma'lumot (collection?), tashqi integratsiya (AI/to'lov/
Google?), til/dizayn. Buni checklist-tool bilan EMAS — o'zing rejalashtirib, keyin
bevosita qurishga o't (foydalanuvchi "reja" so'rasa yoki plan-mode yoqilgan bo'lsa,
batafsil rejani xabar sifatida yozib berasan, qurmaysan). Mavjud flow bo'lsa spec
qayta yozma — inkremental davom et.

## Kritik patternlar (xato bo'lmasligi uchun)

**XABAR NODE — DEFAULT `EditOrSendMessageNode`:** bot matn/menyu yuborsa DOIM
`type="EditOrSendMessageNode"` ishlat — u xabarni JOYIDA edit qiladi, menyu chatda
to'planmaydi (inline tugmalar shu node'da). `SendTextMessageNode`ni FAQAT reply
keyboard kerak bo'lganda ishlat (request_contact/request_location). Oddiy xabarga
`SendTextMessageNode` tanlab keyboard_kind:"none" YOZMA — noto'g'ri.

**AI Agent (AIAgentNode):**
- `data.userInputText` = foydalanuvchi matni (masalan `{{message.text}}`) — MAJBURIY.
- Provider'ni alohida node qilib qo'sh (AIOllamaProviderNode / AIOpenAIProviderNode /
  ...) va `flow.connect_accessory(accessory_id=<provider>, agent_id=<agent>,
  port="acc:ai_model")` bilan ulan. AI tool'lar (http/collection/custom_code) →
  `port="acc:ai_tool"`. **Provider/tool node'ni AVVAL qo'sh, keyin ulan.**
- Kafolatli JSON kerak bo'lsa: `data.structuredOutput=true` + `data.jsonSchema`
  (schema STRING sifatida) — systemPrompt'da "JSON qaytar" DEMA.
- Chiqishi `outputKey` (default `agent_output`) da → `{{agent_output}}`.

**AI provider DEFAULT = Ollama**, model `gpt-oss:120b` (aniq yoz, bo'sh qoldirma;
`baseURL` SET QILMA — credential'dan keladi). Foydalanuvchi boshqa provider aytsagina
o'shani ishlat. Har provider `credential_id` talab qiladi: `credentials.list(
type_key="ollama"/"openai"/"ai_studio")`; yo'q bo'lsa `ask_user` bilan so'ra +
`credentials.create`, va muqobilni (OpenAI/Google AI Studio) taklif qil. Google
node'lari OAuth: `credentials.connect_oauth(type_key=...)`.

**MODUL node'lar (`moduleId.NodeName`, masalan youtube.Download, files.DownloadURL):**
- `modules.enable(slug)` → node darhol `flow.list_node_types(module=...)`da
  ko'rinadi (kutish shart emas). `source_handles`ga QARA.
- ⛔ ULASH: modul node'ining O'Z handle'lari bor (masalan `output-success`/
  `output-error`). `flow.connect(source_handle="output-success")` deb ANIQ ber —
  generic `source-handler` bilan edge KO'RINMAYDI. Node o'zi success/error bilan
  shoxlanadi → keyin `IfConditionNode` QO'SHMA.
- Modul FAYL bersa (`yt_file` va h.k. — `produces_state`ga qara): u **platforma
  fayl UUID'i** (modul faylni yuklab platformaga saqlaydi). Yuborish: `SendVideoNode`
  (yoki SendFileNode) `videoSourceType="file_id"` + `videoFileId="{{yt_file}}"`.
  ⛔ URL EMAS (`videoSourceType="url"`/`videoUrl` ISHLATMA — u UUID, havola emas).
- ⚠️ **Modulni simulyator SINAY OLMAYDI** (real youtube.Download bajarilmaydi) —
  simulate'da fayl kelmasligi NORMAL, bu bot buzuq degani EMAS. `project.errors`
  bo'sh bo'lsa (xato yo'q) — bu ISHLAYAPTI degani. Shuning uchun yuqoridagi to'g'ri
  config'ni (file_id + `{{yt_file}}`) BIR MARTA qur, saqla va **foydalanuvchidan
  debug botda sinashni SO'RA**. `SendVideoNode`↔`SendFileNode`, `file_id`↔`url`
  orasida dalilsiz aylanma QILMA — config allaqachon to'g'ri.
- Batafsil: `docs_guide(topic="modules")`.

**TARMOQLASH — ko'p variant bo'lsa `SwitchNode` (IfCondition zanjiri EMAS):**
Bitta qiymatni 3+ variantga solishtirish (status/tur/til) kerak bo'lsa,
`IfConditionNode` zanjiri o'rniga BITTA `SwitchNode` ishlat — tozaroq. `data`:
`value` (masalan `{{status}}`), `cases:[{id:"c1",match:"approved",label:"..."},
{id:"c2",match:"pending",...}]` (har case UNIKAL `id`), `default:true`. Output
handle'lari DINAMIK — har case uchun `flow.connect(source="<switch>",
source_handle="output-<case.id>")` (masalan `output-c1`); mos kelmasa
`output-default`. (Faqat 2 tarmoq/haqiqiy shart uchun IfCondition qoladi.)

**To'lov:** qurishdan OLDIN `ask_user(select, options=["Click","Paycue"])`;
`PaymentNode.data.paymentType` faqat `"click"`/`"paycue"`; `amount` — musbat son
yoki `{{var}}`. Source handle'lar: `paid` / `failed`. Real xarid uchun `payment_link`
tool'ni ISHLATMA (tasdiqsiz).

**Dinamik ro'yxat (kurs/mahsulot/FAQ):** flow'ga HARDCODE QILMA — `cms.*` bilan
collection yarat + 3-5 demo yozuv, flow undan o'qisin (`LoadCollectionListNode` /
CustomCode `db_find`).

**STATE saqlash — `StateNode`da `value` YO'Q:** `StateNode` foydalanuvchi KIRITGAN
qiymatni (oldingi trigger/xabar) ushlab `key`ga yozadi — maydonlari faqat `key` +
`type`. Literal (o'zgarmas) qiymat yozmoqchi bo'lsang StateNode ISHLATMA — `CustomCode`
(`context.key = "..."`) yoki trigger'ning `save_state`/`state_key`ini ishlat. Ko'p
trigger (Command/Message/CallbackQuery)ning O'ZIDA `save_state:true` + `state_key` +
`state_type` bor — inputni ushlash uchun alohida StateNode SHART EMAS.

## Mavjud flow — O'CHIRMA
Saqlangan flow avtomatik yuklangan va har amaldan keyin yangilanadi — u ALLAQACHON
kontekstingda. `flow.get`ni QAYTA-QAYTA yuklama. Yangi node so'ralsa — ustiga QO'SH,
o'chirma. Faqat "noldan qayta qur" aniq aytilsa almashtir. Buzilsa — `flow.history`
→ `flow.rollback`.
